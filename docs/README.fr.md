# Royaume ONE

**Votre contexte. Vos outils. Vos règles.**

Le Royaume vise à organiser le contexte autour du travail : personnes, entreprises, projets, connaissances, outils et agents. Chacun reçoit les informations utiles à sa mission et des droits d'usage précis.

Un espace individuel et un espace d'entreprise reposent sur le même noyau ; ils ne partagent pas automatiquement leurs données. Jira peut rester l'outil de suivi, Notion la documentation et GitHub la source du logiciel. Le Royaume relie ces outils avec un contexte et des autorisations explicites.

## Ce premier dépôt

Une présentation publique, une démonstration interactive et un moteur de décision minimal testé sur des exemples fictifs. Les contrats des plugins, le modèle économique et la feuille de route sont documentés. Le cockpit privé existant n'est pas copié ici.

L'objectif est open source. Le choix de licence reste à adopter : ce dépôt public n'accorde pas encore de droits de réutilisation. Apache-2.0 est la proposition détaillée dans [le dossier licence](licensing.md).

## Le verrou d'une ressource

Trois réglages compréhensibles : autoriser les agents ; autoriser l'usage pour une finalité précise ; autoriser le partage externe vers une destination précise. Une expérimentation peut rester disponible pour construire et tester, tout en étant exclue d'une candidature commerciale ou d'un portfolio.

Le bouton exprime la règle. Le serveur devra l'appliquer avant toute recherche, lecture et sortie. Ce démonstrateur ne protège pas les comptes connectés existants et n'efface pas les informations déjà envoyées.

Lancer : `npm test`, puis `npm run build`. La suite du cadrage se trouve dans [l'architecture](architecture.md) et [le modèle économique](business-model.md).
