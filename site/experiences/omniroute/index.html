Ce qui a été produit

Le premier agent établit les indicateurs de six missions fictives. Le second identifie les missions bloquées, actives et prêtes. Chaque agent reçoit son propre contexte, demande la lecture des données et soumet un résultat écrit dans un fichier. Le superviseur est un programme déterministe ; il ne s’agit pas d’une délégation décidée librement par un modèle.

Fournisseurs et coût observé

Deux points d’accès publics sans clé fournisseur ont été raccordés à OmniRoute par sa configuration OpenAI compatible : Kilo, route kilo-auto/free, et Pollinations, route openai-fast. Aucun compte externe, abonnement ou crédit payant n’a été créé. Le routeur déclare un coût de 0 pour les appels conservés ; ce chiffre est sa déclaration, sans facture fournisseur indépendante. Le modèle derrière Kilo Auto peut changer et n’est pas attesté par le nom de route.

Incidents et limites constatés

  • Pollinations a renvoyé une limite de gratuité : une réponse toutes les 45 secondes par adresse IP. Un premier parcours a été interrompu ; les points de reprise et l’erreur sont conservés dans le dossier de preuves.
  • La politique de secours du routeur a effectivement changé de fournisseur pendant 1 appel(s) de la recette finale. Une panne HTTP 503 locale a aussi été simulée séparément, puis le fournisseur gratuit sain a répondu.
  • 1 soumission(s) incorrecte(s) ont été refusée(s) par le vérificateur durant cette dernière recette. L’essai précédent contient également une erreur de classement corrigée après refus.
  • Le point de reprise est conservé entre deux processus d’agents ; cela ne prouve pas une reprise après coupure en plein appel réseau ou l’exploitation 24 h/24.
  • La version publiée sur npm était 3.8.54 pendant l’essai, alors que la documentation consultée décrivait 3.8.55. Les raccourcis intégrés testés demandaient des clés ; les points d’accès anonymes ont nécessité une configuration personnalisée.

Contrôle des appels annexes. Un premier lancement a été arrêté par la révision automatique à cause d’un appel externe de diagnostic d’adresse IP. Pour la recette suivante, les services de synchronisation ont été désactivés et le réglage officiel du diagnostic IP a été dirigé vers un point local répondant « indisponible ». Aucune fausse adresse IP n’a été fournie. Les services temporaires de l’essai sont arrêtés.

Portée pour le Royaume

La faisabilité de sous-agents exécutants utilisant des accès gratuits via OmniRoute est établie sur cette mission minuscule. L’intégration au téléchargement du Royaume, l’interface mobile de lancement, l’hébergement durable, les permissions métier et la fiabilité sur de longs travaux restent à construire et à éprouver. Le test a été lancé depuis la conversation ; aucune interface mobile du produit n’a été déployée.
